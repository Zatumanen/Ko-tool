**Дата контрольной точки:** 23 октября 2026. **Статус:** решения владельца для планирования; это НЕ отчёт о завершённой реализации, НЕ разрешение менять код и НЕ подтверждение HIL/CI.

**Репозиторий:** https://github.com/Zatumanen/Ko-tool (основа проекта: https://github.com/di-sukharev/vibe). **Зафиксированный исходный main при создании документа:** 58bcc3e431fc97cb0fb7c69790ba92fc866aff8a. **Linear:** https://linear.app/clouded/project/ko-tool-release-10-2f713ebc0fca.

## 1. Приоритеты и границы релиза

K.O. Tool 1.0 — единый полноценный браузерный продукт. Обязательны шесть **последовательных направлений работы** (не шесть отдельных окон приложения):

1. **My EP** — первая полная функциональная и аппаратная приёмка.
2. **SpeedUpperCut** — после My EP.
3. **Visuals** — после SpeedUpperCut.
4. **Sequencer** — **отдельное приложение / иконка**, после Visuals.
5. **FX-MIC Studio для EP-2350** — отдельное приложение, включая проверенный режим Live, после Sequencer.
6. **EP-136 Sidekick** — после FX-MIC Studio; **интеграция в Visuals, без отдельной иконки**.

Каждый этап завершается по собственным обязательным критериям до перехода к следующему. Внутри этапа **одна инженерная задача за раз**. Порядок определяется критическим путём — неизвестные протокола, безопасность и блокирующие риски исследуются заранее. Если задача аппаратно заблокирована, допустим переход к независимой безопасной задаче **только после отдельного согласования изменения очереди**. Нет параллельной разработки. Сроки не обещать до аудита.

**Релизная модель:** проверенные, независимо законченные улучшения разрешено предлагать к промежуточным публикациям при отдельном согласии владельца. Незавершённые экспериментальные функции должны быть недоступны пользователям. Метка **1.0** только после готовности шести направлений, успешных применимых CI/автоматических проверок, индивидуальных аппаратных/визуальных приёмок и отсутствия критических дефектов. **Дополнительную сверх этих условий общую релизную приёмку владелец НЕ потребовал** (выбран вариант 18.30 A). Все ранее утверждённые тесты приложений обязательны. Merge/deploy только после успешных проверок и отдельного разрешения.

## 2. Поддерживаемая платформа

- **Обязательная приёмка только на macOS 12 Monterey и новее, Google Chrome.**
- **Физический тестовый компьютер:** MacBook Pro 13″ 2017, Intel Core i5, 8 ГБ RAM, macOS Monterey; без обязательного тестирования на Apple Silicon, Windows и Android.
- Для Monterey нужен последний **совместимый** Chrome, а для новых macOS допускается современный Chrome; нельзя обещать, что новейший Chrome поддерживает Monterey. Реальные версии уточнить при тестировании.
- **iPhone — только после 1.0.** Visuals — **только десктоп**.
- За исключением Visuals, критерий производительности — стабильная работа без зависаний, потерь и критических ошибок, **без числовых CPU/RAM/FPS SLA**. Для Visuals действуют отдельные строгие показатели и стресс-тесты.
- Работу Web MIDI/SysEx, USB Audio и firmware-scoped операций нельзя выводить только из названия браузера, модели устройства или наличия USB-порта.

## 3. SpeedUpperCut — утверждённый контракт

- Простой быстрый **пакетный конвертер**: настройки → файл/папка/перетаскивание → обработка → локальное сохранение или передача в My EP. **Не расширять функциональность** без одобрения; пользователь исключил добавление waveform/chop в целевой минималистичный UX. Существующие waveform/chop в main требуют **сверки**, не скрытого удаления как часть документационной работы.
- Ускорение **только ×2** и рассчитанная компенсация playback **sound.pitch = −12** на поддерживаемых EP; без режимов 1×/4×. Выбор **HI/MID/LO**; **Mono/Stereo/Original**; **One Shot/Loop/Original**.
- Best-effort batch: сбой одного файла не уничтожает успешные результаты; понятный отчёт. Локальный экспорт отдельных WAV или ZIP с **сохранением структуры исходных папок**, оригинальных имён/числовых префиксов.
- Drag одного подготовленного сэмпла на конкретный слот My EP. Drag партии на вкладку — предложение распределить по свободным слотам с **предпросмотром и подтверждением**, без скрытой перезаписи.
- **Приёмка:** функция + CI/Unit/E2E + точность ×2/PCM/WAV/метаданных и режимов + физическая цепочка SpeedUpperCut → My EP → настоящий EP; доказать отсутствие **повторного REPITCH**. Дополнительные необязательные стресс-обязательства для SpeedUpperCut сверх этого не вводить.
- Подготовленный через SpeedUpperCut файл не должен автоматически ускоряться второй раз при импорте в My EP.

## 4. My EP — утверждённый контракт

- Реальный аппаратный компаньон. Ориентир пользовательского поведения и операций — **официальный Teenage Engineering EP Sample Tool**, проверяемый по предоставленному JS-снимку/актуальному референсу. Дополнительные защиты K.O. Tool не ослаблять.
- Sample Library: поиск, фильтры, массовый импорт, перетаскивание между вкладками, отображение памяти и честного прогресса. Просмотр/изменение допустимых метаданных PITCH, PLAY MODE, TIME MODE и иных полей через подтверждённые SET/GET + readback. Не путать глобальные настройки сэмпла и настройки назначенного пэда в проекте.
- Взаимодействие с **12 физическими пэдами**: верная раскладка, группа/проект/назначения, клик по UI-пэду должен воспроизводить звук на подключённом устройстве там, где это проверенно доступно; обновление интерфейса при действиях на EP. Настройки и ссылки в нескольких проектах менять **только в соответствии с достоверным поведением firmware**, не предполагать автоматическую общую синхронизацию.
- **Projects:** лишь просмотр проектов **P01–P09** и резервное копирование/проверенное восстановление, плюс назначение сэмплов на пэды; **не создавать самостоятельный полнофункциональный редактор проектов**, не добавлять создание/удаление/копирование проекта без нового решения.
- **REPITCH:** прямой импорт неподготовленных WAV в My EP с автоматической подготовкой ×2/−12 по одобренному контракту; уже подготовленные файлы SpeedUpperCut нельзя повторно обрабатывать. **Метаданные pitch=-12 сами по себе НЕ доказывают**, что PCM уже ускорен: нужен достоверный признак происхождения/содержимого и безопасное определение. Указанный в ранних документах переключатель REPITCH ON/OFF — сверить с фактическими последними решениями перед изменением UI; не вводить ошибочный детектор по одному pitch.
- Загружать партии по **плану с предварительной проверкой** файлов, памяти, занятых и свободных слотов; показывать конфликт/варианты; явное подтверждение → последовательная проверенная запись каждого файла → детальный итог. Сохранять успешные файлы, не перезаписывать молча; неизвестное состояние останавливает очередь.
- **Отмена и прогресс — максимально повторять согласованный референс**. Проверить конкретные условия остановки/очереди по исходному EP Sample Tool до кодовых изменений. Не прерывать FILE в небезопасной точке ради UI; ошибки и отмену отражать достоверно.
- **Диагностика (вариант C):** сообщения для пользователя в логике референса, раскрываемые технические сведения и **экспорт обезличенного лога** по согласию пользователя; без приватных SysEx, серийников, содержимого проектов и секретов по умолчанию.
- **Безопасность данных (вариант C):** READ без backup; изменения метаданных — снимок исходных значений и readback; MOVE/COPY/DELETE и проекты — подтверждённый backup, проверки зависимостей, FILE-транзакции, CRC, journal, recovery; восстановление только после проверки совместимости и согласия. Для удаления используемого сэмпла дополнительное информированное подтверждение; неподтверждённую физическую операцию не обходить.
- **Обрыв USB (вариант C):** остановить/инвалидировать сессию, сохранить журнал; после подключения проверить SKU, точную прошивку и фактическое состояние; **не повторять запись автоматически**; предложить только безопасные разрешённые пути восстановления.
- **Аппаратные блокировки (18.6 B):** продолжаем безопасные задачи My EP, не ослабляя guards; при строгой очередности задач изменение порядка — по согласованию. Следующее приложение нельзя начинать до **полной функциональности, зелёного CI и необходимой аппаратной приёмки** My EP (18.7 B).
- **EP-1320 Medieval (18.32 A):** сохраняем **только подтверждённые** существующие возможности. Распознавание ≠ разрешение WRITE. Не обещать полную совместимость проектов/секвенсора.
- EP-133/EP-40: все права на FILE/SysEx/проекты определяются **точным SKU и firmware-scoped evidence**, а не только handshake; неизвестное — fail closed.

## 5. Sequencer — отдельное приложение

- **Самостоятельное окно и иконка** в K.O. Tool; не как вкладка/дочерняя функция My EP. Работает только при физически подключённом/авторизованном EP; **не offline DAW**.
- Основной интерфейс — **Step Sequencer**; **Piano Roll** для отображения высоты/длительности нот. Аппаратные сцены, паттерны, шаги, события, транспорт и сохранение — **строго в рамках реально доступных функций EP**.
- Live-редактирование во время проигрывания и **двусторонняя синхронизация**, физическое EP — источник истины при конфликте; устаревший UI никогда не должен перезаписывать более новое состояние устройства.
- Не делать собственный несогласованный SAVE/autosave, playhead, DAW-функции или эмуляцию аппаратных операций.
- **Приёмка:** **каждая операция отдельно** — источник/протокол → безопасный Unit/fake-EP сценарий → разрешённый HIL с exact firmware, readback и проверкой ошибок/конфликтов. Если операция недоступна или небезопасна, **владелец принимает индивидуальное решение**: продолжать исследование, блокировать или явно исключить; не сокращать scope молча.
- Старые docs/SEQUENCER.md, AGENTS.md и Linear ZAT-63 всё ещё описывают Sequencer внутри My EP / Saved read-only; это **расхождение** с новым владельческим решением. В документационной ревизии отметить, при разработке отдельно обновить с разрешением.

## 6. Visuals — семь модулей + рекордер

**Источник** — один явно выбранный браузерный аудиовход (микрофон, интерфейс/line-in); НЕ захват общего системного звука и НЕ MIDI; один источник одновременно для всех визуализаторов и рекордера, без скрытого переключения/автовыбора.

Обязательные модули:
1. **Waveform:** транзиентный trigger-режим по видео владельца/AliExpress-референсу: ровная линия до атаки слева, фронт близко к середине, затухание вправо, удержание до следующего удара; настройки sensitivity, time/amplitude scale, hold.
2. **Spectrum:** мягкая плавная кривая по эстетике FabFilter Pro-Q3; не добавлять EQ/Range/Tilt/Freeze.
3. **Spectrogram:** временная история прокручивается **справа налево**, новые столбцы справа; длительность истории и детализация адаптивны размеру модуля/нагрузке.
4. **XY Oscilloscope:** точный Stereo XY (L→X, R→Y) плюс отдельно маркированный **Artistic XY** для моно/эстетики; естественное фосфорное послесвечение, без отдельного trail-контроля.
5. **Loudness:** реальный **LUFS** по ITU-R BS.1770, Momentary 400 мс, Short-term 3 с, Integrated за измерение и reset; не выдавать RMS dBFS за LUFS.
6. **Stereo Meter:** Voxengo MSED-подобный read-only **Plasma Vector Scope** (главный), компактные **Correlometer** и **Stereo Balance**; без Mid/Side обработки или панорамирования.
7. **Output Meters:** только L/R **Peak Meter**, Peak Hold и предупреждение CLIP; без RMS/True Peak.

**WAV Recorder:** selectable **16/24-bit PCM**, START/STOP/PAUSE/RESUME, таймер, input level/CLIP, предпрослушивание, discard/save; один выбранный аудиовход.

**Темы: строго три:**
- **App Colors:** улучшенный Retro Windows (серая/тёмно-синяя/teal основа).
- **Device Colors:** максимально верные оттенки отдельной подключённой модели **EP-133 / EP-40**; определять модель достоверно, не по названию аудиоустройства.
- **Black & White:** в рамках одной темы переключение **Dark Mono / Light Mono**; строго монохромные сигналы ошибок/CLIP без красных исключений.

**Производительность:** широкий спектр железа, приёмка на выбранном MBP 2017; адаптивное **60/30/15 FPS**, сокращение нагрузки только на отрисовку, не на точность измерений/аудиозапись; offscreen suspension кроме нужных для рекордера/LUFS задач. Отдельные количественные CPU/GPU/RAM/FPS и baseline-регрессии устанавливаются **только после измерений**. Стресс-тесты: **15 минут** семь модулей одновременно, **1 час** активное переключение/запись, **4 часа** endurance/leaks/нагрев/обрывы/целостность WAV. **Каждый из семи модулей отдельно** сравнивается с референсом и принимается владельцем; затем общая техническая приёмка.

## 7. FX-MIC Studio / EP-2350 — обязательно в 1.0

Существующая задача [ZAT-50](https://linear.app/clouded/issue/ZAT-50/fx-mic-studio-podderzhka-ep-2350-posle-stabilizacii-dejstvuyushego-ko) ранее предполагала отложенный модуль и исследовательский Live. **Новое решение владельца для 1.0 заменяет прежнюю очередность и делает проверенный Live обязательным.**

- Отдельное окно/иконка, **НЕ** EP-133 FILE/SysEx.
- Автономный **Sample Pack Builder**: 4 WAV-слота, обрезка, формат/длина/ёмкость, набор с config.json, строгая валидация и ZIP.
- **FX Chain Editor:** 4 пресета, параметры, порядок эффектов и корректность ссылок row; **Modulation Designer:** рычаг, shake, LFO/маршрутизация; локальные пресеты и обратимый import/export.
- **Emulation:** интерактивное браузерное приближение, явно не равное реальному звучанию железа.
- **Live:** аппаратное управление допустимыми настройками физического EP-2350 по подтверждённому USB протоколу и реальное прослушивание через звуковой тракт устройства; референс **A Thing for Ting**. Не путать simulated preview и Live. Доступность Web Serial/MicroPython, безопасный режим и firmware должны быть проверены на реальном устройстве; **никакой неподтверждённой установки/замены прошивки**.
- Backup, подтверждение опасных изменений, безопасное восстановление/отключение, отдельные HIL и владельческая приёмка. Если Live физически неподтверждён — этап не завершён без отдельного решения владельца.

**Инженерный паспорт задачи**: назначение/поведение, исходные функции и файлы, первоисточники (URL/hash/offset при необходимости), зависимость-предшественник, критерии приёмки, риски, сценарии ошибок и rollback, применимые unit/E2E/CI/HIL, точный SKU/firmware, владелец приёмки; сложность **S/M/L/XL**, диапазон трудозатрат и уверенность без выдуманных сроков. **Стандартные статусы Linear**, контрольные точки отдельно. **Последовательные задачи** — каждая после предыдущей, очередность критическим путём. Приоритет ошибок: сохранность данных → блокирующие регрессии → функциональные зависимости → некритичный долг. Не рефакторить рабочий код ради рефакторинга. При аппаратной блокировке возвращаться за согласованием очереди, не имитировать проверки.

**Аудит** — сначала архитектура/безопасность My EP → остальные пять в порядке. Проверить main, все открытые PR/diff/CI, данные Linear; классифицировать: готово, требует доработки, конфликтует, устарело. Старые PR **не закрывать/не мержить** автоматически. Например, при первичной проверке: main 58bcc3e, PR #137 closed/unmerged, PR #139 и #110 open Draft. Это **временной снимок**, перепроверить перед дальнейшими действиями.

**Отчёт** в двух уровнях: общий обзор шести этапов/рисков и подробный инженерный план с доказательствами. Для релизной приёмки отсутствие доказательств ≠ успешный тест. Имеющиеся fake-EP тесты ≠ новая HIL-проверка.

**Разделение разрешений:**
1. Сначала read-only аудит и проект полного роадмапа.
2. Отдельно владелец утверждает содержание.
3. Отдельно разрешает перенести/актуализировать задачи Linear.
4. Отдельно — любые **правки кода**, GitHub PR/merge/deploy или опасные hardware-write/HIL сценарии по согласованному scope; документационные правки и фиксация решений, разрешённые **23.10.2026**, не разрешают реализацию функций.
5. Слияние только после **завершённого успешного CI** и отдельного согласия владельца. Не менять main напрямую.
